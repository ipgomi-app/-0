# 입고미회수 전산개선 건의서

**작성** : 부산권역 이민승 프로
**수신** : 영남영업본부장님 / (경유) 시스템즈
**일자** : 2026년 8월
**첨부** : 부산권역 테스트 앱 화면, 스마트라토스 현행 화면

## 1. 배경 및 경위

부산권역 입고미회수 실적이 본부 내 최하위 수준으로 저조하여, 원인 규명을 위해
**담당자–차량기사 면담 및 현장 동행 방문**을 실시하였습니다.

전산개선을 시스템즈에 의뢰하기 전, **제 판단이 실제 현장에서 유효한지 검증하는 것이 우선**이라 판단하여
부산권역 내에서 소규모 테스트를 진행하였습니다. 사전 보고를 드리지 못한 점 양해 부탁드립니다.

테스트에 적용한 항목은 **기존 스마트랜스에 이미 구현되어 있는 기능 범위**를 벗어나지 않으며,
새로운 기능 창출이 아니라 **"기사–담당자 간 정보 단절"이라는 가설의 검증**이 목적이었습니다.

### 1-1. 면담·현장방문을 통한 진단 (2가지)

| 구분 | 진단 내용 | 결과 |
|---|---|---|
| **차량기사** | 자산관리 등 일부를 제외한 대부분의 기사는 기존 실물회수 업무에 집중.<br>**사전 확인이 안 된 업체는 방문하지 않음** | 입고미회수 대상 업체가 동선상에 있어도 방문 누락 |
| **담당자** | 입고미회수 종이 출력물 전달 여부가 담당자별로 제각각.<br>사전 확인 내용을 카톡/유선으로 전달한 뒤 **사후 이행 여부를 확인하지 않음** | 확인–전달–회수의 연결고리 단절, 동일 업체 반복 연락 |

> **핵심 문제** : 확인한 정보(담당자)와 회수를 실행하는 인력(기사) 사이에
> **시스템으로 연결된 공유 채널이 없고, 카톡·유선·종이에 의존**하고 있음.
> 매일 전화하고, 카톡 보내고, 잊어버리고, 또 연락하고, 다시 확인하는 **반복 루프**가 발생.

## 2. 테스트 앱 실사용 결과

### 2-1. 강점 (현장에서 효과가 확인된 부분)

| # | 기능 | 실사용 효과 |
|---|---|---|
| 1 | **처리사유 표준 11종 선택** (다음에 회수협의 / 회수완료 / 회수거부 / 확인불가(분실) / 입고오류(전화) / 되가져감 / 다른곳 출고 / 이전·폐업 / 중복코드·대상제외 / 계약처·재입고 / 영업지원 전달) | 서술형 보고가 사라지고 **원인이 코드로 표준화** → 담당자·기사 모두 동일한 언어로 소통. 사유별 집계가 자동 산출 |
| 2 | **전달사항(메모) 상호 공유** | 담당자가 사전 확인한 내용이 **기사 화면에 그대로 표시**. 카톡·유선 재확인 루프 제거 |
| 3 | **처리 즉시 팀 전체 동기화** | 한 사람이 처리하면 **전원 화면에서 해당 업체가 사라짐** → 중복 방문·중복 연락 원천 차단 |
| 4 | **업체 클릭 시 입고내역 즉시 표시** | 현장에서 "어디서 입고된 물량이냐"는 업체 문의에 **즉답 가능** → 분쟁·설득 시간 대폭 단축 |
| 5 | **GPS 반경 기반 근접 업체 표시 + 지도 마커** | 기사가 현재 위치 주변의 입고미회수 업체를 **동선상에서 즉시 인지** → "가는 김에 회수" 발생 |
| 6 | **다음 회수협의 건 예정일·수량·연락처 등록** | 협의 건이 잊히지 않고 **예정일에 재노출** → 후속 이행률 확보 |
| 7 | **업무일지 문안 자동 생성 + 카톡/복사 공유** | 처리 즉시 일지 문안이 완성되어 **일지 작성 시간 절감**, 기재 누락 방지 |
| 8 | **오프라인 처리 및 자동 재전송 대기열** | 지하·창고·음영지역에서도 처리 가능, 통신 복구 시 자동 전송 → **입력 유실 없음** |
| 9 | **담당자별·사유별 처리 통계** | 권역/지점 단위로 **누가 무엇을 얼마나 처리했는지** 즉시 확인 |

### 2-2. 한계·단점 (개인 테스트 도구의 구조적 제약)

> 아래 항목들이 **"테스트로 끝내고 회사 앱에 반영해야 하는" 근거**입니다.

| # | 한계 | 리스크 |
|---|---|---|
| 1 | **원천 데이터가 실시간이 아님** — 백데이터를 수동으로 갱신해야 하므로 스마트랜스 실적과 **시차 발생** | 이미 회수된 건이 잔존 표시 → 헛방문·업체 신뢰 저하 |
| 2 | **사내 시스템과 미연동 → 이중 입력** — 앱에서 처리 후 스마트랜스에 다시 입력 | 담당자 업무 가중, 장기 운영 불가 |
| 3 | **외부 무료 인프라 의존** (구글 스크립트 기반 동기화) | 처리량·속도 한계, 서비스 중단 시 대응 불가 |
| 4 | **개인 제작·개인 관리** | 인사이동 시 유지관리 단절. **회사 자산이 아닌 개인 도구**로 남음 |
| 5 | **업체 연락처 등 개인정보를 사외 경로로 취급** (암호화 적용했으나 사내 통제 밖) | 정보보안 관점에서 **정식 운영 부적합** |
| 6 | **권한 체계가 단순** (공용 인증, 감사로그 미비) | 권역·지점별 접근 통제 및 이력 추적 불가 |
| 7 | **별도 앱 설치 필요** — 로지스올앱·스마트라토스와 별개 아이콘 | 기사 입장에서 **앱을 2개 보는 부담**, 현장 정착률 저하 |
| 8 | **부산권역 데이터에 한정** | 전 권역 확산 불가 |

> **결론** : 기능적 효과는 검증되었으나, **운영 지속성·보안·데이터 정합성 측면에서 개인 도구로는 확대 불가**.
> 동일 기능을 **회사 정식 시스템(스마트랜스 / 로지스올앱 / 스마트라토스)에 반영**하는 것이 유일한 해법입니다.

## 3. 회사 앱 현행 기능과의 비교

현행 **스마트라토스**는 이미 `특이지점 > 입고미회수 / 당월미방문 / 재고증가 / 물류센터` 메뉴와
`거리순 / 라우팅순` 정렬, 지도 마커 표시를 보유하고 있습니다.
**즉 "위치를 보여주는" 단계까지는 이미 구현되어 있으며, 신규 개발이 아니라 기존 기능의 확장입니다.**

| 항목 | 스마트라토스 / 스마트랜스 (현행) | 테스트 결과 필요 확인 사항 |
|---|---|---|
| 입고미회수 대상 **위치 표시** | ✅ 특이지점 메뉴로 구현됨 | — |
| 거리순 / 라우팅순 정렬 | ✅ 구현됨 | — |
| **확인 사유(원인) 입력·공유** | ❌ 없음 (카톡·유선·종이) | **필요** |
| **담당자↔기사 메모 상호 공유** | ❌ 없음 | **필요** |
| **담당자 확인 완료 업체 별도 표기** | ❌ 없음 | **필요** |
| **업체 클릭 시 입고내역 즉시 조회** | △ 여러 단계 조작 필요 | **개선 필요** |
| 처리 결과 팀 실시간 반영 | △ 반영 시차 존재 | 개선 권장 |
| 사유별·담당자별 통계 | ❌ 수기 집계 | 개선 권장 |

## 4. 건의사항

### 【건의 1】 기사–담당자 간 업체 확인내용 상호 공유 (최우선)

- **요청** : **로지스올앱 ↔ 스마트랜스 연동**으로, 담당자가 사전 확인한 내용을
  기사 화면에서 바로 확인하고, 기사의 현장 처리 결과가 담당자에게 즉시 반영되도록 개선
- **입력 방식** : 서술형이 아닌 **원인 사유 선택(약 9~11종) + 추가 메모** 방식
  → 입력 부담 최소화, 통계 자동화 동시 확보
- **역할 분담** : **데이터 처리 = 담당자 / 실물 회수 = 기사**로 명확히 분리하되 정보는 공유
- **개선 효과** : 매일 전화·카톡·재확인의 **반복 루프 제거**, 처리 효율 직접 상승

### 【건의 2】 담당자·영업지원 확인 완료 업체의 스마트랜스 별도 표기

- **요청** : 담당자 또는 영업지원이 **사전 확인을 완료한 업체**를 스마트랜스(특이지점 목록·지도 마커)에
  **별도 색상/아이콘/뱃지로 구분 표시**
- **개선 효과** : 기사가 방문 즉시 **분쟁 없이 바로 실물 회수** 가능
  → 현행 진단 1번(“사전 확인이 안 된 업체는 가지 않는다”)의 **직접적 해소책**

### 【건의 3】 업체 클릭 시 입고내역 원클릭 조회

- **요청** : 스마트랜스에서 업체 선택 시 **최근 입고내역(입고처·입고일·수량·품목)이 한 화면에 즉시 표시**
- **현행 문제** : 현장 방문 시 업체가 “어디서 입고된 것이냐”를 문의 → 확인에 여러 번의 조작 필요, 응대 지연
- **개선 효과** : 현장 즉답 가능 → 회수 거부·분쟁 감소

## 5. 기대효과

1. **회수율 개선** — 사전 확인 업체의 방문 누락 해소로 실물회수 전환율 상승
2. **업무시간 절감** — 담당자–기사 간 반복 연락 및 사후 확인 루프 제거
3. **현장 분쟁 감소** — 입고내역 즉시 제시로 회수 거부·이의 제기 감소
4. **관리지표 확보** — 사유별 통계로 회수 불가 사유(폐업·이전·입고오류 등)의 **구조적 원인 파악 및 데이터 정비**
5. **전 권역 확산 가능** — 개인 도구가 아닌 회사 시스템으로 표준화

## 6. 요청사항

1. 상기 건의 1~3번을 **입고미회수 전산개선 요청 건**으로 시스템즈에 정식 의뢰 요청드립니다.
2. **추가 개선 요청 사항이 있으시면 조언 부탁드립니다.** 취합하여 요청서에 반영하겠습니다.
3. 부산권역 테스트 결과(화면·처리 데이터)는 **요청 근거 자료로 첨부** 가능합니다.
4. 테스트 도구는 **검증 목적 한시 운영**이며, 회사 앱 반영 시 **즉시 사용 중단**하겠습니다.
